# Voice Router

Гибридный голосовой AI-робот с LLM-слоем выбора сценария.

> Голосовой робот хорошо слышит, но сценарий разговора выбирает классификатор, который ломается на живой речи и смене языка. LLM-слой по контексту выбирает сценарий и не затягивает паузу дольше секунды.

**Владелец задачи:** Halyk Bank

**Кейс:** HackAlem AI 2026 — Voice Router

## Проблема

Клиент контакт-центра взаимодействует с роботом, который хорошо распознаёт и синтезирует речь, но выбирает сценарий с помощью классификатора на энкодерной модели. При смене темы, запросах на стыке сценариев или переходе между русским и казахским языками такой классификатор может направить разговор по неверному пути. В результате клиента переводят на оператора, а иногда он вовсе прекращает разговор.

Voice Router должен заменить традиционный классификатор намерений LLM-слоем, который учитывает контекст диалога, выбирает подходящий сценарий и позволяет продолжить разговор без лишней задержки.

Оценивается прежде всего **качество маршрутизации**, а не качество распознавания или синтеза речи. Скорость выбора сценария оценивается отдельно и даёт дополнительные баллы.

## Пользователи

### Клиент контакт-центра

Клиент говорит своими словами, а робот:

1. Понимает суть запроса с первой реплики.
2. Запускает подходящий сценарий.
3. При смене темы переключает сценарий, не теряя контекст.
4. Помогает закрыть вопрос без участия оператора.

### Супервизор

Супервизор видит:

- транскрипт разговора;
- выбранные сценарии;
- обоснование выбора;
- альтернативные сценарии;
- случаи неуверенности и ошибок;
- задержку каждого этапа обработки.

## Задача

Разработать голосового AI-робота с веб-интерфейсом симуляции. Робот должен принимать речь через микрофон, учитывать историю диалога и с помощью LLM выбирать один из доступных сценариев. Пользователь получает голосовой ответ, а супервизор — подробную трассировку решения.

## Входные данные

- Голосовая речь через микрофон.
- Текст как резервный и дополнительный канал.
- Русский и казахский языки, включая переключение языка внутри диалога.
- Каталог из 40 сценариев.
- До 10 реплик в одном диалоге.

Пример составного запроса:

> Здравствуйте, я вчера оплатил, деньги списались, а заказ не подтвердился… а, и ещё, адрес доставки поменять надо.

## Результат

### Для клиента

- голосовой ответ;
- корректный переход в выбранный сценарий;
- сохранение контекста при смене темы.

### Для супервизора

- транскрипт реплики;
- выбранный сценарий и обоснование;
- альтернативные сценарии;
- задержка по этапам обработки.

Целевые показатели задержки:

- выбор сценария — около **500 мс**;
- от конца реплики до начала ответа — не более **1,5 секунды**.

Показатели отображаются в интерфейсе и учитываются при оценке, но не являются условием сдачи.

## Данные стартового кита

Стартовый кит выдаётся в день хакатона и включает:

| Файл                  | Содержимое                                                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `scenarios.json`      | 40 сценариев: назначение, границы с соседними сценариями, параметры, действия, примеры запросов и ответов на русском и казахском |
| `dialogs_sample.json` | 10 размеченных диалогов, включая смену темы и смешанную речь                                                                     |
| `knowledge_base.json` | Факты о компании для формирования ответов                                                                                        |
| `mock_backend.json`   | Тестовые клиенты и данные для выполнения действий                                                                                |
| `dev_utterances.json` | Размеченные реплики для локальной проверки маршрутизации                                                                         |
| `evaluate.py`         | Скрипт самостоятельного измерения точности                                                                                       |

Компания в данных вымышленная и относится к страховой отрасли. Каталог обезличен и не содержит реальных клиентских данных. Добавлять собственные сценарии разрешено, но оценка проводится по исходным 40 сценариям.

Использование собственных моделей допускается, однако не даёт преимущества само по себе: задача посвящена маршрутизации, а не сравнению речевых моделей.

## Must-have

| Требование                      | Проверка                                                                                                                                                 |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Голосовое взаимодействие в вебе | Жюри говорит в микрофон, робот распознаёт речь и отвечает голосом. Текст используется только как дополнение.                                             |
| Выбор сценария на LLM-слое      | Команда демонстрирует устройство слоя. Intent-классификатор энкодерного типа не засчитывается.                                                           |
| Корректность выбора             | Жюри проверяет 10 одинаковых для всех команд реплик: простые, со сменой темы, смешанной речью и на стыке сценариев. Оценивается доля правильных ответов. |
| Панель трассировки              | После каждой реплики отображаются сценарий, обоснование, альтернативы и время по этапам.                                                                 |
| Русский и казахский             | В проверочном наборе есть две реплики на казахском и одна реплика со смешением языков внутри фразы.                                                      |

Десять проверочных реплик и ожидаемые сценарии хранятся у жюри и заранее командам не выдаются.

## Опциональные возможности

- Гибридная маршрутизация: быстрый путь для очевидных запросов и LLM для сложных случаев.
- Измеримое приближение к задержке выбора сценария в 500 мс.
- Удержание контекста и возврат к прерванной теме.
- Уточняющий вопрос вместо угадывания при недостаточной уверенности.
- Передача оператору вместе с накопленным контекстом.
- Извлечение параметров из речи.
- Потоковая обработка.
- Определение эмоции и адаптация тона ответа.
- Статистика ошибок в панели супервизора.
- Редактирование каталога сценариев без участия разработчиков.

## Статус проекта

Реализован локальный контур Phase 1: текст из Vue проходит через H3 в `handleTurn`, маршрутизируется серверным адаптером `gpt-realtime`, проверяется по каталогу и превращается в короткий ответ с трассировкой. Без `OPENAI_API_KEY` endpoint возвращает явный статус `unavailable`; мок не подменяет провайдера.

```sh
pnpm install --frozen-lockfile
pnpm run setup
pnpm dev
```

Для live-маршрутизации укажите серверный `OPENAI_API_KEY` в локальном `.env`. Ключ не должен иметь префикс `VITE_` и не попадает во frontend. Проверки без платных вызовов:

```sh
pnpm run check
pnpm run verify
```

Отдельный live-eval запускается только при настроенном ключе и сохраняет результаты в `artifacts/router-eval/`:

```sh
pnpm run eval:router
python data/voice-router/evaluate.py artifacts/router-eval/predictions.json data/voice-router/dev_utterances.json
```

STT, TTS, VAD, браузерный звонок и исполнение действий не входят в Phase 1 и пока не реализованы.
