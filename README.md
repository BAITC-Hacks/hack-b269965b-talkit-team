# Voice Router — голосовой AI-робот с LLM-слоем выбора сценария

Кейс HackAlem AI 2026. Владелец задачи — **Halyk Bank**. Демонстрационная компания — **Saqta Insurance**, вымышленная страховая из набора организатора, а не продукт банка.

## Задача простыми словами

Обычный голосовой робот может правильно услышать слова, но выбрать не тот сценарий: например, спутать «я только что попал в ДТП» со «заявление о ДТП уже подано, какой статус?». Ещё сложнее, когда клиент меняет тему, задаёт два вопроса сразу или переключается между русским и казахским.

Voice Router заменяет классификатор намерений на LLM-слой. Модель читает реплику, контекст и каталог сценариев; сервер проверяет решение и формирует ответ по данным Saqta. Клиент получает ответ, а супервизор — транскрипт, сценарии, краткое обоснование, альтернативы и измерения времени.

Оценивается прежде всего **правильность маршрутизации**, не качество голоса. В кейсе — 40 сценариев, диалоги до 10 реплик и 10 скрытых проверочных реплик жюри, включая RU, KK и смешанную речь. Ориентиры — 500 мс на выбор сценария и 1,5 с от конца речи до начала звука. Это измеряемые бонусные показатели, не гарантии текущей реализации и не условия допуска. Полное задание — [TASK.md](TASK.md).

## Как проходит одна реплика

```text
Микрофон браузера → PCM → WebSocket сервера
                          ├─ OpenAI: транскрипт + определение конца речи (VAD)
                          └─ Yandex: второй транскрипт
                                   ↓
                        DSR: выбрать текст или переспросить
                                   ↓
Текстовый чат → HTTP → общий handleTurn
                       → LLM route_turn по каталогу и контексту
                       → проверка ID/слотов → policy → ответ по фактам
                                   ↓
Голосовой канал: ElevenLabs TTS → PCM → воспроизведение в браузере
Текстовый канал: JSON → чат
Оба канала: решение и доступные диагностические данные
```

DSR — согласование двух распознаваний, не второй классификатор сценариев. При финальных согласующихся гипотезах приоритет у OpenAI; Yandex может дать резервный текст. Конфликт чисел или отрицания приводит к переспросу без запуска предметного маршрута. Работа одного STT помечается как деградация.

LLM получает исходные описания сценариев, границы `not_this_if`, примеры и слоты. Ожидаемые ответы eval-набора в prompt не передаются. Policy выносит срочные SC11/SC15/SC38 вперёд, запрашивает недостающие данные, уточняет неуверенные решения. Два последовательных решения с низкой уверенностью могут дать `handoff` — это решение маршрутизатора, не состоявшийся звонок оператору.

«Гибридный» здесь означает сочетание LLM, проверяемых серверных правил и прямых ответов. Отдельного доказанного быстрого пути выбора намерения с выигрышем по задержке пока нет.

## Ожидаемое поведение: примеры для проверки

Это ориентиры по каталогу, **не результаты выполненного live-теста**.

| Реплика                                           | Ожидаемый смысл и маршрут                                                          |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| «Деньги списались, а полис не оформлен»           | SC30 — проблема оплаты/оформления, запрос недостающих данных без обещания возврата |
| «Выплату одобрили, но сумма слишком маленькая»    | SC19 — несогласие с решением, не SC17 «статус»                                     |
| «Полисімді ұзартқым келеді»                       | SC27 — продление полиса; ответ на казахском                                        |
| «Полисімді ұзарту керек, и ещё добавить водителя» | SC27 + SC04 — два намерения, смешанная речь                                        |
| «Где ваш офис? А сейчас я попал в ДТП»            | SC11 обрабатывается раньше информационного SC33                                    |
| «Вы выдаёте кредиты?»                             | `SYS_OUT_OF_SCOPE` — Saqta не выдаёт кредиты                                       |
| «Помогите с этим» без контекста                   | `SYS_UNCLEAR` / уточнение, а не угадывание                                         |

В одной сессии продолжение вроде «А какие документы нужны?» должно учитываться вместе с предыдущим вопросом. Смена темы должна менять сценарий. Эти случаи нужно проверять отдельно от одиночных реплик; примеры диалогов лежат в `dialogs_sample.json`.

## Запуск: сначала без внешних API

Нужны Node.js `>=24.21.0 <25` и pnpm `10.28.0`. Для голосового пути OpenAI дополнительно нужен `ffmpeg` в `PATH`: он переводит входной PCM 16 кГц в 24 кГц. Для локальных тестов, текстового пути и сборки ffmpeg не требуется. Python 3 нужен только для `evaluate.py`; Docker — только для контейнерного запуска.

Все команды ниже выполняются **из корня репозитория**.

```sh
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm dev
```

Открыть `http://127.0.0.1:5173`. API — `http://127.0.0.1:3000`; Vite проксирует `/api`, включая WebSocket. В Windows, если политика PowerShell запрещает `pnpm.ps1`, используйте `pnpm.cmd`.

Файл `.env` **не обязателен для запуска приложения**. Не создавайте фиктивные ключи: непустая заглушка включает попытку обращения к настоящему API.

| Конфигурация                                 | Что доступно                                                | Что ожидаемо не работает                                                             |
| -------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Нет `.env` и нет ключей в окружении процесса | Страница, health/echo, reset, сборка, локальные тесты       | Текстовый turn: `status: "unavailable"`, без решения; голос: `STT_UNAVAILABLE`       |
| Только рабочий `OPENAI_API_KEY`              | Реальная текстовая маршрутизация; с ffmpeg — OpenAI STT/VAD | Yandex отсутствует, DSR деградирован; голосовой ответ не озвучивается без ElevenLabs |
| OpenAI + обе настройки ElevenLabs            | LLM и одно-STT голосовой путь с озвучкой                    | Нет второй гипотезы Yandex                                                           |
| Все семь настроек провайдеров + ffmpeg       | Полный предусмотренный голосовой путь                       | Всё ещё нужны доступные модели/голос, права, квоты, сеть и live-проверка             |
| Только Yandex или ElevenLabs, без OpenAI     | Может быть доступен отдельный речевой адаптер               | Они не заменяют LLM-router; успешной предметной маршрутизации нет                    |

Отсутствие файла не означает отсутствие ключей: окружение процесса тоже читается. `pnpm dev` и `pnpm start` дополнительно загружают `.env` при его наличии; уже заданные переменные процесса имеют приоритет. Прямой `node dist/server/index.js` сам `.env` не загружает.

`GET /api/health` проверяет приложение, **не** OpenAI, Yandex или ElevenLabs. Надпись «API доступен» не подтверждает готовность голосового робота.

## Настройки: полный справочник без доступа к чужому .env

Можно передавать настройки через окружение процесса/менеджер секретов или создать локальный файл:

```sh
pnpm run setup
```

Команда копирует безопасный шаблон [.env.example](.env.example) и не перезаписывает существующий файл. Значения ключей в Git не сохраняются. Источники конфигурации: [env.ts](src/server/env.ts) и [provider-config.ts](src/server/features/voice-router/provider-config.ts).

### Настройки приложения

| Переменная | По умолчанию       | Назначение                                                                               |
| ---------- | ------------------ | ---------------------------------------------------------------------------------------- |
| `NODE_ENV` | `development`      | `development` / `test` / `production`. Только production включает раздачу собранного web |
| `HOST`     | `127.0.0.1`        | Адрес сервера; `0.0.0.0` нужен для входа извне контейнера/хоста                          |
| `PORT`     | `3000`             | Порт HTTP и WebSocket; `0` используется тестами для свободного порта                     |
| `WEB_PORT` | `5173`             | Порт Vite в dev; отдельного Vite в production нет                                        |
| `APP_NAME` | `HackAlem Starter` | Имя приложения в API; непустая строка до 80 символов, не выбор сценария                  |

Произвольных `VITE_*`-ключей для работы не требуется. Префикс `VITE_` не использовать для секретов: такие значения могут попасть в браузерную сборку.

### Настройки провайдеров

| Переменная                           | Что именно требуется                                                                                                                                          | Что ломается без неё                                                          |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `OPENAI_API_KEY`                     | Серверный API-ключ проекта OpenAI с доступом к используемым Realtime/STT-моделям и доступной квотой                                                           | LLM-router и OpenAI STT/VAD                                                   |
| `YANDEX_SERVICE_ACCOUNT_ID`          | ID сервисного аккаунта Yandex Cloud Kazakhstan                                                                                                                | Вместе с остальными Yandex-полями включает второй STT                         |
| `YANDEX_SERVICE_ACCOUNT_KEY_ID`      | ID авторизованного ключа этого же сервисного аккаунта, не API-ключ                                                                                            | Подпись JWT / получение IAM-токена                                            |
| `YANDEX_SERVICE_ACCOUNT_PRIVATE_KEY` | Соответствующий приватный RSA-ключ в PEM; строка ключа, не путь к файлу                                                                                       | Подпись JWT; код поддерживает настоящие переводы строк и литеральные `\n`     |
| `YANDEX_FOLDER_ID`                   | ID каталога, в котором аккаунту разрешено распознавание речи                                                                                                  | Авторизация SpeechKit и привязка запроса к каталогу                           |
| `ELEVENLABS_API_KEY`                 | API-ключ аккаунта ElevenLabs с доступом к TTS и выбранному голосу                                                                                             | Озвучка; текст и результат маршрутизации не заменяются выдуманным звуком      |
| `ELEVENLABS_VOICE_ID`                | **Существующий voice ID голоса, уже загруженного/добавленного в аккаунт, которому принадлежит `ELEVENLABS_API_KEY`.** Ключ должен иметь доступ к этому голосу | Озвучка; произвольное имя голоса, ID модели или недоступный голос не подходят |

Для ElevenLabs сначала добавьте/загрузите голос в нужный аккаунт, скопируйте его Voice ID и используйте ключ того же аккаунта. Само заполнение двух строк не проверяет их совместимость: неверный или недоступный ID выявится при реальном TTS-запросе.

Модели фиксированы в коде: `gpt-realtime` (маршрутизация и генерация текста), `gpt-4o-transcribe` (OpenAI STT), `eleven_v3` (TTS). Переменных `OPENAI_MODEL` / `TTS_MODEL` / `TALKIT_API_KEY` приложение не читает. Нет зависимости от API TalkIt, БД, Redis, Telegram, банковского или настоящего страхового backend.

### Что отправляется во внешние API и что ожидается в ответ

| Интеграция          | Запрос приложения                                                                                                                         | Требуемый результат                                                               |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| OpenAI LLM          | Server-to-server `wss://api.openai.com/v1/realtime?model=gpt-realtime`, Bearer API key, каталог/контекст/реплика                          | Структурированный `route_turn`; затем при необходимости текст по выбранным фактам |
| OpenAI STT/VAD      | Отдельная Realtime-сессия `?intent=transcription`, PCM 24 кГц после ffmpeg                                                                | Частичные/финальные транскрипты и события начала/конца речи; не ответ клиенту     |
| Yandex IAM          | `POST https://iam.api.yandexcloud.kz/iam/v1/tokens` с подписанным PS256 JWT                                                               | IAM-токен; приложение получает и кеширует его само                                |
| Yandex SpeechKit v3 | gRPC/TLS `stt.api.ml.yandexcloud.kz:443`, IAM Bearer + `x-folder-id`, PCM 16 кГц                                                          | Вторая гипотеза распознавания для DSR, не сценарий и не синтез                    |
| ElevenLabs          | `POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}/stream?output_format=pcm_16000`, `xi-api-key`, текст + `model_id: eleven_v3` | Бинарный поток PCM16 mono 16 кГц; не JSON, не MP3                                 |

Для Yandex сервисному аккаунту нужны права распознавания на каталог, например `ai.speechkit-stt.user`. В этой реализации выбран способ JWT → IAM, а не передача статического `YANDEX_API_KEY`. Официальные справочники: [OpenAI WebSocket authentication](https://developers.openai.com/api/docs/guides/voice-websockets), [права Yandex SpeechKit](https://yandex.cloud/ru-kz/docs/speechkit/security/), [ElevenLabs stream API](https://elevenlabs.io/docs/api-reference/text-to-speech/stream).

Проверьте доступность именно зафиксированных моделей перед демо: документация провайдеров может уже показывать другие версии. Актуальность аккаунта, тарифа, квоты и модели не определяется наличием строки в окружении. В коде нет автоматической замены модели или браузерного TTS при ошибке.

Голос уходит настроенным STT-провайдерам, текст/контекст — в OpenAI, текст ответа — в ElevenLabs. Для демонстрации используйте синтетические данные. Не вводите реальные персональные или банковские сведения.

## Как пользоваться симулятором

1. Для проверки интерфейса откройте страницу без ключей и отправьте текст: ожидается явная недоступность модели.
2. Для реального текстового демо настройте OpenAI, перезапустите сервер и отправьте одну из реплик выше. Справа появится основной сценарий, альтернатива, причина и доступные timings.
3. Для голоса подготовьте ключи, ffmpeg и браузер с микрофоном. Нажмите визуализатор «Позвонить» и разрешите доступ.
4. Говорите после состояния «Слушаю вас». OpenAI VAD завершает реплику после паузы; кнопка «Закончить реплику» — ручной резерв.
5. Проверьте обе гипотезы, DSR, маршрут и статус озвучки внутри голосовой карточки. «Говорить снова» начинает следующий ход; повторное нажатие на визуализатор завершает звонок.
6. «Отменить реплику» / «Прервать ответ» останавливает текущую операцию. Новая текстовая сессия сбрасывается отдельно.

Текстовая и голосовая сессии сейчас **раздельные**: одна и та же серверная логика не означает общий контекст UI. Правая панель показывает текстовый канал; голосовые результаты отображаются в своей карточке.

Микрофон требует secure context: localhost/loopback или HTTPS. Открытие `http://IP:5173` с другого устройства не равно рабочему голосовому демо. Отсутствующие timings показываются «—». `Total` справа — сумма измеренных серверных этапов, не сквозное время до начала звука; факт генерации аудио не равен его воспроизведению.

| `GET /api/health`              | Жив ли сервер                                                                                          |
| `POST /api/echo`               | Starter-проверка JSON/Unicode; не LLM                                                                  |
| `POST /api/voice-router/turn`  | Текстовый ход: UUID сессии/хода, `text` 1–4000 символов, `source: "text"`                              |
| `POST /api/voice-router/reset` | Сброс состояния по `sessionId`                                                                         |
| `WS /api/voice-router/ws`      | Голосовой протокол из [src/shared/voice.ts](src/shared/voice.ts); не отправка произвольного аудиофайла |

Пример для PowerShell:

```powershell
$turnBody = @{
  sessionId = [guid]::NewGuid().ToString()
  turnId = [guid]::NewGuid().ToString()
  text = "Деньги списались, а полис не оформлен"
  source = "text"
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:3000/api/voice-router/turn -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($turnBody))
```

Без ключа корректный HTTP-запрос получает HTTP 200 и предметный `status: "unavailable"`, исходный `selectedText` и `trace`; `decision`/успешный ответ не придумываются. С рабочим ключом `completed` содержит `decision`, `plan`, `answer`, языки и `trace`; `completed` **не означает исполнение страховой операции**.

Повтор той же пары `sessionId`/`turnId` с тем же телом возвращает тот же результат, с другим телом — 409. Невалидный ввод — 400; неверный метод — 405; нехватка ёмкости хранилища сессий — 503. Для продолжения сохраняйте `sessionId`, но создавайте новый `turnId`. Reset принимает `{"sessionId":"ваш UUID"}`.

## Production и деплой

### Node без Docker, в том числе без файла .env

```sh
pnpm run build
```

В PowerShell, в отдельном терминале сервера:

```powershell
$env:NODE_ENV = "production"
$env:HOST = "127.0.0.1"
$env:PORT = "3000"
node dist/server/index.js
```

В POSIX shell:

```sh
NODE_ENV=production HOST=127.0.0.1 PORT=3000 node dist/server/index.js
```

Прямой запуск выше не читает `.env`; ключи при необходимости заранее подаёт окружение/менеджер секретов. Для загрузки локального `.env` вместо `node ...` используйте `pnpm start`, **сохранив `NODE_ENV=production`**. Сам `pnpm start` production-режим не устанавливает.

Сервер раздаёт UI, HTTP и WS на одном порту `3000`. На хосте должны оставаться `package.json`, runtime-зависимости `node_modules/`, `dist/` и **весь `data/`**: JSON и proto загружаются во время работы, в JS-бандл они не вшиты.

### Docker/Compose: локальный запуск без API по умолчанию

```sh
docker compose up --build -d
docker compose logs --tail=100 app
pnpm run smoke -- http://127.0.0.1:3000
docker compose down
```

Dockerfile устанавливает ffmpeg, работает от `node` и запускает production. Compose публикует `127.0.0.1:3000` и не передаёт провайдерские переменные; `.env` автоматически не становится окружением контейнера. Поэтому стандартный запуск выше не включает платные API.

Проверьте Dockerfile, из которого собран ваш образ: локальный вариант с `ENTRYPOINT ["/usr/bin/env", "-u", ...]` дополнительно **удаляет все семь переменных провайдеров**. В таком образе даже передача ключей через Compose/`-e` не включает live API; это ограничение образа, не неисправность ключа.

Для живого демо используйте описанный Node-запуск с контролируемым доступом. Live-контейнер требует безопасной передачи всех нужных переменных через runtime-окружение/менеджер секретов и отсутствия удаления этих переменных в ENTRYPOINT. Не считайте локальный Compose без ключей готовым live-деплоем.

### Публикация за reverse proxy

1. Разместите production-процесс и зависимости на сервере; установите ffmpeg. Не публикуйте dev-сервер Vite.
2. Поставьте перед приложением HTTPS reverse proxy. WebSocket должен проходить с `Upgrade`/`Connection`, сохранением внешнего `Host` и согласованным браузерным `Origin`: сервер отвергает несовпадение host.
3. Защитите UI, HTTP turn и WS внешней авторизацией/ограничением доступа и расходов **до** подключения платных ключей. В приложении нет пользовательской авторизации или полноценного rate limit.
4. Запустите `pnpm run smoke -- https://ваш-домен`, отдельно откройте UI и проведите звонок с другого устройства.
5. Зафиксируйте URL, версию, фактический результат и известные ограничения в `docs/progress/`. HTTPS и зелёный health сами по себе не подтверждают голос.

Сессии хранятся в памяти одного процесса: перезапуск их теряет. Несколько реплик/инстансов без отдельного решения по состоянию не обеспечивают общий контекст. Голосовой transport ограничен 16 одновременными соединениями, 20 ходами на соединение, 15 минутами сессии и 60 секундами входного аудио за ход. Это защитные пределы кода, не нагрузочный тест и не требование кейса «10 реплик».

## Тесты и оценка

```sh
pnpm run check
pnpm run verify
```

| Команда                   | Что реально проверяет                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------ |
| `pnpm run typecheck`      | Серверные, Vue и инструментальные типы                                                                 |
| `pnpm test`               | Node-тесты из `tests/**/*.test.ts`                                                                     |
| `pnpm run check`          | Typecheck + тесты                                                                                      |
| `pnpm run doctor`         | Node, lockfile, H3 1.x и наличие `.env`; не валидность ключей                                          |
| `pnpm run format:check`   | Форматирование; исходный датасет исключён через `.prettierignore`                                      |
| `pnpm run build`          | Сервер `dist/server` и web `dist/web`; предварительно очищает сгенерированный `dist`                   |
| `pnpm run smoke:built`    | Временно запускает собранный сервер без OpenAI: health, echo, API 404, unavailable/reset, SPA и assets |
| `pnpm run verify`         | Doctor → format:check → check → build → smoke:built                                                    |
| `pnpm run smoke -- <URL>` | Только health, echo и API 404 указанного сервера; не UI/голос/точность                                 |
| `pnpm run format`         | Изменяет форматирование файлов; перед запуском учитывать чужие правки                                  |

Есть особенность **doctor**, а не приложения: локально он требует существующий `.env` даже без ключей. Можно выполнить `pnpm run setup`, оставив все секреты пустыми. Для проверки в среде без файла предусмотрен `CI=true`: PowerShell `$env:CI = "true"` или POSIX `CI=true pnpm run verify`. Это пропускает только требование файла, не проверки типов/тестов.

Локальные тесты покрывают каталог, prompt без expected-разметки, policy, repair, состояние/отмену/повторы, HTTP/JSON, DSR-конфликты и деградацию, fake STT/TTS, WebSocket-протокол, PCM, playback, API-клиент и SSR страницы. Они не расходуют квоты и не доказывают доступность моделей, качество RU/KK, работу настоящего микрофона или достижение 500 мс / 1,5 с.

Если на ограниченной машине SSR/сборка завершается из-за нехватки памяти, ранее помогали временные переменные `RAYON_NUM_THREADS=1` и `NODE_OPTIONS="--max-old-space-size=512 --max-semi-space-size=4"`. Это ограничение окружения, не отключение тестов; сохраняйте фактический результат проверки.

### Живой dev-eval: платные запросы, запускать осознанно

При согласованном использовании API и рабочем `OPENAI_API_KEY`:

```sh
pnpm run eval:router
python data/voice-router/evaluate.py artifacts/router-eval/predictions.json data/voice-router/dev_utterances.json
```

Runner вызывает реальный router для всех 104 реплик, каждую в отдельной сессии без диалоговой истории. Он записывает/перезаписывает `artifacts/router-eval/predictions.json`, `details.jsonl` и `run.json` (модель, prompt hash, версия данных, число ошибок). Ошибка API даёт пустое предсказание, не правильный ответ. Проверяйте `failed` в `run.json`: завершение скрипта само по себе не означает успешность всех запросов.

`evaluate.py` не обращается к API и не генерирует предсказания: он считает primary accuracy (первый ID), full match (совпадение наборов) и intent recall для multi-intent. Его запуск с уже имеющимся файлом возможен без ключей. Эти метрики не оценивают звук, продолжение диалога или фактическую задержку воспроизведения.

Отдельная live-приёмка: RU, KK, mixed, смена темы, несколько намерений, переспрос, отмена, ошибка провайдера и звук на другом устройстве. Не подставлять ожидаемые ответы и не публиковать фиктивные проценты. [Порядок проверки](docs/runbooks/VALIDATION.md).

## Безопасность, данные и незавершённая работа

- Все клиенты, полисы, цены и правила Saqta синтетические; это не реальные продукты Halyk и не юридическая консультация.
- Дата симуляции — `2026-10-01`: «завтра» в данных означает `2026-10-02`, не завтра от системных часов.
- Исходные JSON/разметку/evaluator не менять ради метрик. README набора содержат отдельно помеченное пояснение интеграции.
- Приложение не совершает реальные страховые операции, платежи, SMS или звонки операторам. Mock backend пока является набором данных, не запущенным backend-сервисом.
- Нужны дальнейшая реализация mock executor/подтверждений/handoff, полные сквозные timings, live-eval и публичное защищённое демо.
- Секреты остаются на сервере; их значения не нужны для чтения документации или локальных тестов.
- Происхождение starter/данных/стороннего кода и разрешения раскрываются в [compliance](docs/compliance/PREEXISTING.md); отчёт или commit не доказывает конкурсное время создания.
