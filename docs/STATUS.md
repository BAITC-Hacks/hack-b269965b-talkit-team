## Текущая задача и следующий шаг

- Активная фаза: Phase 2. Локальный STT/DSR/TTS и browser transport подключены; `speech_stopped` автоматически завершает текущую реплику. Следующая реплика запускается вручную. Live-приёмка остаётся открытой.
- В текущем рабочем дереве OpenAI final выдаётся по VAD `item_id` без прежней фиксированной задержки 600 мс; Yandex EOU отправляется на той же границе. Финал Yandex больше не сокращает срок ожидания OpenAI. Незавершённый Yandex EOU не загрязняет следующий ход: тот временно идёт без Yandex. Локальные DSR и adapter-тесты прошли, но новый живой звонок и полная транспортная гонка двух провайдеров не проверялись.
- При TTS-исключении сервер передаёт `failed` вместе с безопасной категорией ошибки и HTTP-статусом, если он есть; начало воспроизведения объявляется только с первым PCM-фреймом. Конкретная причина предыдущего живого сбоя не установлена. Следующий шаг — пользовательский повторный звонок на обновлённом сервере, проверка Router trace и разбор показанного кода озвучки без раскрытия ключей; агенту платный тестовый вызов не разрешён.
- Новый `route.completed` обновляет голосовой результат до начала потоковой озвучки; страница показывает предварительный TTS `pending`, затем итог из `turn.completed`. После изменения WebSocket-контракта для живой проверки нужны новый сервер и обновлённая страница.
- Публичный voice WebSocket не требует кода доступа по решению пользователя; перед публичным развёртыванием нужны внешняя аутентификация и лимиты расходов для платных путей. Разрешение на pre-existing starter и перенос внутреннего речевого кода по-прежнему отмечено как неподтверждённое в [PREEXISTING.md](compliance/PREEXISTING.md).
