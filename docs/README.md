# Документация Voice Router

Этот раздел помогает понять задачу хакатона, найти владельца нужной части кода, воспроизвести запуск и отличить план от проверенной функции. Владелец кейса — Halyk Bank; робот работает с синтетической страховой Saqta Insurance.

## С чего начать

1. [Корневой README](../README.md) — задача простыми словами, текущие возможности, примеры, все ключи и API, запуск без `.env`, production/Docker, тесты и ограничения.
2. [TASK.md](../TASK.md) — требования и критерии приёмки: голос, LLM-маршрутизация 40 сценариев, RU/KK/mixed и трассировка. Скорость 500 мс / 1,5 с — ориентиры для измерения.
3. [STATUS.md](STATUS.md) — актуальный снимок и ссылки на фактические проверки.
4. [AGENTS.md](../AGENTS.md) и [PREEXISTING.md](compliance/PREEXISTING.md) — правила работы и раскрытие заранее созданных материалов.

Не нужно получать чужой `.env` для знакомства с проектом: безопасный шаблон находится в [.env.example](../.env.example), полный смысл каждой переменной — в корневом README. Значения секретов в документацию не добавляются.

## Что реализовано сейчас

В `src/web/App.vue` подключена страница Voice Router, не Echo. Текстовый запрос проходит HTTP → `gpt-realtime` → валидацию/policy → ответ по знаниям. Голос проходит WebSocket → OpenAI/Yandex STT → DSR → тот же обработчик → ElevenLabs → браузерный звук. Голосовая и текстовая сессии пока раздельные.

В UI есть выбранные сценарии, причины, альтернативы и доступные серверные timings; голосовая карточка также показывает распознавания, DSR и статус доставки звука. Неизмеренные этапы нельзя считать нулевыми, а сумму серверных этапов — полной задержкой.

Mock executor, подтверждения и полноценный перевод оператору ещё не завершены. Live-точность, задержки и публичное демо не подтверждаются наличием адаптеров или локальных тестов. Подробности — в [STATUS.md](STATUS.md).

## Ожидаемый результат и пример

Для «Деньги списались, а полис не оформлен» ожидается SC30, объяснение выбора и уточнение недостающих параметров. Это пример требования, не утверждение о точности модели.

В отчёте разделяйте:

- что реализовано в коде;
- что проверено локально с подменёнными API;
- что проверено с настоящими ключами/микрофоном;
- что не проверено и остаётся открытым.

`status: "completed"` означает завершённую обработку маршрута/ответа, не реальную выдачу полиса. `handoff` в плане — не доказательство связи с оператором.

## Запуск и проверка документации на практике

Из корня репозитория, Node.js 24.21+ в ветке 24.x и pnpm 10.28.0:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Без файла и ключей открывается `http://127.0.0.1:5173`, текстовый маршрут возвращает `unavailable`, голос — `STT_UNAVAILABLE`. Для локального `doctor`/`verify` выполните `pnpm run setup` с пустыми ключами или используйте предусмотренный `CI=true` для проверки без файла.

```sh
pnpm run check
pnpm run verify
```

`verify` включает doctor, форматирование, типы/тесты, build и smoke собранной SPA; не вызывает платные модели. `pnpm run smoke -- <URL>` проверяет только health/echo/API 404. Live-eval (`pnpm run eval:router`) отдельно расходует квоту OpenAI.

Production требует `NODE_ENV=production`, `dist/`, runtime-зависимости и `data/`. Compose по умолчанию не передаёт ключи; если Dockerfile содержит ENTRYPOINT с `env -u`, он дополнительно удаляет их даже при явной передаче. Полные команды Node, Docker, HTTPS/WS и защиты доступа — в [разделе деплоя](../README.md#production-и-деплой).

Для TTS нужны обе настройки ElevenLabs: `ELEVENLABS_VOICE_ID` — существующий голос, добавленный в аккаунт ключа `ELEVENLABS_API_KEY` и доступный этому ключу. Наличие ключа без такого голоса не обеспечивает озвучку.

## Как поддерживать документы

1. Сверить `TASK.md`, исходный набор, код и `package.json`. В фазах описана цель, а не автоматически достигнутый результат.
2. После изменения поведения обновить корневой README и README затронутого раздела.
3. Запустить соответствующие проверки, записать команду, результат, ограничения и следующий шаг в новый `progress/*.md`.
4. Обновить `STATUS.md` ссылкой на отчёт. Коммит, push, URL и метрики указывать только после фактического выполнения.
5. Не переписывать старые отчёты так, будто новые функции существовали раньше.

JSON-набор организатора и его evaluator не корректируются ради оценок. В его трёх README сведения об интеграции отделены от исходного описания. Не добавляйте реальные ключи, клиентские данные или чувствительные provider-логи.
