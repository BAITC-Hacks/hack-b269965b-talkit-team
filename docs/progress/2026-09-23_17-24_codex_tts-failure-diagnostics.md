# Уточнение сбоя озвучки

Фактическое время записи: 23 сентября 2026, 17:24, Asia/Qyzylorda (UTC+05:00).

## Изменения

- Сервер теперь объявляет `response.audio.start` только при первом PCM-фрейме, а не до запроса TTS. При сбое до первого фрейма не создаётся ложное окно начатой озвучки.
- В `turn.completed.result.tts` при ошибке передаются только безопасные `kind`, `httpStatus` (если есть) и число переданных PCM-байт. Ключ, текст ответа и тело ошибки провайдера не передаются. UI различает отказ провайдера, транспортную, протокольную и ошибку доставки; при нуле аудио сообщает, что звук не поступил в браузер.
- Обрыв HTTP-аудиопотока классифицируется как транспортная ошибка без раскрытия приватного текста исключения. Добавлен локальный регрессионный тест.
- Сверка с официальным API не обнаружила несовместимости используемого HTTP Stream endpoint, модели `eleven_v3` и формата `pcm_16000`; модель и голос наугад не заменялись.

## Проверки и ограничение

- `pnpm run check` прошёл: типы и 89/89 тестов.
- `pnpm run verify` прошёл: doctor, формат, типы, 89/89 тестов, production build и built smoke.
- Живой запрос к ElevenLabs не выполнялся по указанию пользователя. Исходная причина `TTS: failed` не установлена; возможный HTTP-статус станет виден только при следующем контролируемом звонке на обновлённом сервере. Локальный smoke не проверяет внешний TTS и воспроизведение в браузере.

Следующий шаг: перезапустить сервер на обновлённом коде, сделать один пользовательский звонок и сообщить показанные `kind`/HTTP-статус без ключей и содержимого `.env`. Исправлять настройки провайдера следует по этому факту, не подменяя голос или модель предположением.
