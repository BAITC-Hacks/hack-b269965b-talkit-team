# Ранний результат маршрутизатора до озвучки

Фактическое время записи: 23 сентября 2026, 17:46, Asia/Qyzylorda (UTC+05:00).

## Изменение

Ранее сервер отправлял результат маршрутизации только в `turn.completed` после окончания TTS-потока. Первые PCM-фрагменты приходили раньше, поэтому звук мог начаться до обновления «Последнего результата» и Router trace.

- После завершения `controller.handleTurn` сервер отправляет отдельное `route.completed` с валидированным результатом маршрутизатора до запуска TTS. `turn.completed` остаётся итоговым событием после TTS и не меняет жизненный цикл хода.
- Браузер показывает решение, ответ и trace сразу при `route.completed`, отмечая TTS и доставку аудио как `pending`. По итоговому `turn.completed` заменяет предварительный результат окончательным статусом озвучки. Голосовой компонент сообщает странице об обоих обновлениях.
- В браузерном клиенте восстановлена глубокая неизменяемость входящего результата для обоих событий. Тест на неизменяемость вложенных полей уже был в рабочем дереве, но прежняя поверхностная заморозка его не выполняла.

## Проверка и границы

- Локальные тесты WebSocket-контракта и браузерного клиента проверяют раннее обновление, сохранение незавершённого хода, итоговую замену статуса TTS и неизменяемость вложенных данных.
- `pnpm run verify` прошёл: doctor, формат, типы, 98/98 тестов, production build и built smoke.
- Платные запросы и интерактивный звонок не выполнялись. Для живой проверки нужен перезапуск сервера и обновление страницы, поскольку WebSocket-контракт изменился. Сбой внешнего TTS из предыдущего звонка этим изменением не устраняется; он диагностируется отдельно. Замеры `STT` и `TTS first` по-прежнему отсутствуют.
