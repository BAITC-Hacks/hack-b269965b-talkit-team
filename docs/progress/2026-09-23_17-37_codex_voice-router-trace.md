# Голосовой результат в Router trace

Фактическое время записи: 23 сентября 2026, 17:37, Asia/Qyzylorda (UTC+05:00).

## Причина и изменение

Правая панель читала только результат текстового HTTP-канала. Голосовой WebSocket уже передавал `decision` и `trace` в `turn.completed`, но они оставались внутри `VoiceCallPanel`, поэтому после голосовой реплики справа сохранялось «ожидание».

- `VoiceCallPanel` теперь один раз сообщает странице о новом `lastTurnResult`; повторные обновления состояния воспроизведения не дублируют событие.
- Страница показывает последний завершённый результат соответствующего канала. Для голосового результата она отделяет поля DSR/TTS от результата маршрутизатора и проверяет его существующей схемой `turnResultSchema`. Дополнительный HTTP/LLM-запрос не выполняется.
- Подпись справа указывает голосовой или текстовый канал. `STT` и `TTS first` по-прежнему остаются «—», потому что эти этапы ещё не измеряются в серверной трассе; интерфейс явно отличает отсутствие замера от нулевой задержки. `Router`, `Response`, выбранный сценарий, язык, причина и доступные альтернативы берутся из фактического результата маршрутизатора.

## Проверка и ограничения

- Локальный WebSocket-тест проверяет сохранение `decision` и `trace` вместе с отказом TTS и совместимость основной части результата с `turnResultSchema`.
- `pnpm run typecheck` и `pnpm run verify` прошли: формат, типы, 90/90 тестов, production build и built smoke.
- Интерактивный браузерный звонок и внешний TTS здесь не запускались; пользователь запретил платный тестовый запрос. SSR-тест проверяет начальную страницу, но не интерактивное Vue-событие. Повторная проверка в браузере на обновлённой сборке остаётся нужна.
