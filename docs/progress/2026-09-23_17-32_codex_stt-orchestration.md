# Границы реплик и согласование двух STT

Фактическое время записи: 23 сентября 2026, 17:32, Asia/Qyzylorda (UTC+05:00).

## Изменения

- OpenAI `speech_stopped` для уже привязанного к текущему ходу `item_id` закрывает реплику, сразу отправляет Yandex EOU и уведомляет браузер. Пришедшие после границы PCM-кадры учитываются для подтверждения `audio.stop`, но больше не передаются провайдерам. Ручной `audio.stop` остаётся рабочим путём и не повторяет Yandex EOU.
- Финал OpenAI передаётся в DSR по завершённому VAD `item_id`, без прежней фиксированной задержки 600 мс и без склейки нескольких элементов в один авторитетный транскрипт. Неизвестная или чужая поздняя VAD-граница не закрывает новую реплику.
- Если Yandex дал финал первым, DSR ждёт OpenAI до ограниченного общего дедлайна; если OpenAI дал финал первым, оставляет короткое окно для проверки критических расхождений Yandex. Отказ OpenAI допускает ранний Yandex fallback. Одно решение запускает не более одного `handleTurn`; поздние результаты остаются диагностикой.
- Новый ход использует Yandex только при чистой границе его потока: без ожидающего EOU и незакоммиченного буфера. При прерывании потоки сбрасываются; незавершённый OpenAI после обычного хода также не переносится в следующий ход. Повторный warm-up опирается на существующее соединение каждого адаптера.

## Проверки и ограничения

- `pnpm run check`: типы и 90/90 тестов прошли. Добавлены регрессии для приоритета OpenAI, проверки конфликтов после его финала и состояния Yandex до/после EOU.
- `pnpm run verify`: doctor, формат, типы, 90/90 тестов, production build и built smoke прошли.
- Живой двухпровайдерный звонок и внешний TTS после изменений не проверялись: платные вызовы без отдельного разрешения не выполнялись. Существующие тесты транспорта проверяют контракт без настроенных провайдеров; interleaving всех событий OpenAI/Yandex в WebSocket-транспорте пока не воспроизводится интеграционным тестом. Это ограничение локальной проверки, а не подтверждение live-готовности.

Следующий шаг: перезапустить сервер и выполнить один контролируемый пользовательский звонок; проверить, что `speech_stopped` завершает ход, оба STT финала попадают в одну DSR-запись при своевременном ответе, а при опоздании OpenAI fallback явно отмечен как degraded. Отдельно сверить безопасный TTS-код ошибки, если звук снова не поступит.
