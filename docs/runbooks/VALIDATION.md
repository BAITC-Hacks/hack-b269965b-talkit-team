# Как проверять проект

Это порядок проверки, не журнал успешных запусков. Текущий снимок — [STATUS.md](../STATUS.md); результаты — в `docs/progress/`.

## 1. Найти реальные команды

Сначала прочитай `package.json`, принятый lockfile и корневой `AGENTS.md`. Ниже команды из исходной инструкции starter; их наличие и точное поведение нужно сверить с текущей версией репозитория. Не добавляй вымышленные scripts и не меняй версии автоматически.

```sh
pnpm install --frozen-lockfile
pnpm run setup
pnpm run check
pnpm run verify
```

`setup` используй по его фактическому контракту, не перезаписывай имеющиеся локальные настройки и секреты. При наличии установленного корректного окружения не переустанавливай зависимости на каждом локальном шаге без причины.

## 2. Разделять результаты

В исходном starter `verify` описан как общая проверка диагностики, форматирования, типов, тестов, сборки и built smoke. Изучай реальный script; остановка любого шага означает, что весь запуск не завершён успешно.

При остановке `verify` допустимо отдельно запустить оставшиеся проверки, когда это безопасно:

```sh
pnpm run build
pnpm run smoke:built
```

Их успех не заменяет успешный `verify`. Не отключай тесты и форматирование ради зелёного результата. Фиксируй exit status и точную причину остановки.

## 3. Проверки Voice Router

Unit-тесты, типы и сборка должны быть отделены от платных API. Тестовый адаптер обозначается как fake/mock, не как проверенный провайдер.

Для маршрутизатора запускай реально реализованный eval runner по [фазе 5](../implementation/phases/05_EVALUATION.md). Сохраняй predictions, вывод исходного evaluator, модель/конфигурацию и версию кода/промпта. Разметку expected не передавай в runtime.

Отдельно проверяй многоходовые диалоги и реальный голос на русском, казахском и смешанной речи. Текстовый eval не подтверждает микрофон, DSR, воспроизведение или сквозную задержку.

Финальная приёмка — корневой TASK.md, раздел 11, и [SUBMISSION.md](SUBMISSION.md). Не дублируй здесь все требования вторым чек-листом.

## 4. Записать доказательство

После шага добавить запись в `docs/progress/`: фактическая дата/часовой пояс, цель, затронутые файлы, команды и результаты, ошибки, не выполненные проверки, версия/commit при наличии и следующий шаг. Интегратор обновляет STATUS ссылкой на эту запись.

Без ключа, браузера или deployment-доступа соответствующая проверка имеет статус «не проверено/недоступно», а не «успешно». Результат из чужого отчёта помечается как переданное свидетельство, не собственный запуск.
