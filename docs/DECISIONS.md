# Решения и противоречия

Здесь фиксируются только принятые инженерные решения, необходимые трактовки неоднозначных данных и нерешённые расхождения источников. Планируемое решение помечается как предложение; не выдавать его за утверждённое правило хакатона.

Исходное состояние: записи о новых продуктовых решениях в этой реорганизации не добавлялись. Условия TASK сохранены. Предложение о структуре документов описано в корневом MIGRATION.md и требует применения в рабочем репозитории.

## Формат записи

```text
ID / фактическая дата:
Статус: предложено / принято командой / ждёт ответа организатора / заменено
Вопрос:
Источники и точные конфликтующие положения:
Решение или временная трактовка:
Кем подтверждено и где:
Последствия для кода, тестов и документов:
Что остаётся неизвестным:
```

Не создавать отдельный ADR на каждую мелкую правку. Изменение локального компонента, форматирование или перенос файла отражать в progress, если они не меняют договорённость. Не скрывать расхождение TASK, источника организатора и API-справки под видом «очевидного исправления».
