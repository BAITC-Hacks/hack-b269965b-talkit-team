# Параллельная работа

## A — интегратор / ведущий coding-агент

Владелец package.json/lockfile, root configs, src/shared, server startup/routes, controller/state/actions и deployment. Принимает совместные контракты. Только он интегрирует правки общих файлов. Не является владельцем каждой строчки speech/UI.

## B — AI и речь

Владелец router/prompts, openai-realtime adapter, DSR/OpenAI/Yandex/ElevenLabs adapters, сценариев проверки провайдеров, eval-router и анализа ошибок. Поскольку объём большой, интегратор забирает mock-исполнитель, а C — браузерный capture/playback по согласованному контракту. Не менять package.json молча: сообщать нужную зависимость A.

## C — Vue, browser audio, QA и документы

Владелец страницы, микрофона/воспроизведения, useVoiceSession, TracePanel/DsrPanel, пользовательских состояний, playback timing, README/demo и независимых голосовых проверок. Работать по общим DTO; начальные UI-заглушки явные и не считаются настоящей интеграцией.

## Контрольные точки

Сначала согласовать TurnInput/RouteDecision/TraceEvent. Пока B делает route, C делает UI, A делает входной endpoint и загрузку данных. Проверка доступности speech начинается сразу, не после завершения всего текстового кода. Интегрировать маленькие законченные изменения, а не ждать полной «ветки всех сценариев».

Если coding-агент один, следовать фазам последовательно. Если используются subagents, ограничить каждого конкретными файлами; общий контекст задачи и граничные DTO одинаковы. Это параллельные разработчики, а не новая multi-agent архитектура самого продукта.
