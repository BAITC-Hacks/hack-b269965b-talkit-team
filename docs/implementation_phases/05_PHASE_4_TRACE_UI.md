# Фаза 4 — супервизор и измерения

## Задание

1. Заверши одну страницу Vue: разговор и управление микрофоном слева; сценарии, причина, альтернативы, параметры, действия, подтверждение и контекст справа. Покажи активный и отложенные сценарии раздельно. Добавь кнопку новой сессии и экспорт JSON trace. Никакого личного кабинета, CRM, редактора сценариев или отдельного dashboard.
2. Покажи DSR: исходные тексты OpenAI/Yandex, финализированный текст, источник/причина выбора, статус обоих провайдеров, ожидание, опоздавшие результаты и degraded. Не показывай только «DSR включён», когда второй провайдер не работает.
3. После каждой пользовательской реплики сохраняй trace с sessionId/turnId. reason — короткое обоснование по наблюдаемому тексту и границе сценария, а не запрос/показ внутренних рассуждений модели. Уверенность модели обозначай как оценку, не статистическую вероятность.
4. Измеряй: момент окончания речи на временной шкале входного аудио; получение VAD-события; готовность финального STT; дополнительное ожидание DSR; route start/end; action start/end; первый текст ответа; TTS request/first audio; начало воспроизведения. Продолжительность всей речи и задержка после её окончания — разные показатели.
5. Сквозная voice latency = начало фактического воспроизведения − конец речи клиента. Отмечай конец речи через sample offset/временную шкалу аудио, а не просто время доставки VAD-события. Сопоставляй media timeline с browser clock. Не вычитай performance.now() сервера из performance.now() браузера. Если точное сопоставление не сделано, явно показывай proxy-метрику «после получения VAD», не называя её конкурсной.
6. Покажи этапы и total отдельно. Не суммируй перекрывающиеся STT/DSR/LLM интервалы как последовательные. До получения playback-start total = pending/null, а не вымышленный ноль. Текстовые ходы помечай text; не смешивай их total со статистикой голосовых.
7. Вычисляй медиану только по реально завершённым голосовым ходам; рядом sample count и число ошибок/отмен. Не улучшай метрику ранним filler «секундочку» вместо содержательного ответа. Отдельно отмечай cold start и прогретый путь.
8. Покажи состояния disconnected/connecting/listening/recognizing/thinking/speaking/error. Соединения и очереди воспроизведения очищаются при смене сессии. Trace не содержит ключей, production-данных и лишних персональных идентификаторов.

## Проверка

Внешний проверяющий после произвольной реплики видит обе гипотезы, один выбранный маршрут/набор, объяснение, состояние действия и фактическую задержку до голоса. Отказ провайдера и перебивание видны, старое аудио не возвращается.
