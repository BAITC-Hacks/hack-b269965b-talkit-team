# Фаза 6 — воспроизводимость и сдача

## Задание

1. Проверь чистую установку по lockfile и существующий pnpm run verify: диагностика, типы, тесты, build и smoke. Добавь smoke новой функциональности, не ограничивайся старым echo endpoint.
2. Убедись, что data/voice-router попадает в build/runtime image и читается без случайной зависимости от cwd. Не отправляй полный mock_backend браузеру. Проверь compose runtime env, production WebSocket upgrade, закрытие сессий и корректную выдачу статических файлов.
3. README должен содержать назначение, схему DSR → route → action → response → TTS, реальные модели и внешние зависимости, получение ключей без секретов, предварительные шаги и одну команду запуска. Предпочти уже поддерживаемый pnpm dev; Docker-команду обещай только после фактической проверки. Для удалённого микрофона нужна корректная безопасная browser-среда; localhost проверь отдельно.
4. Отдельно опиши synthetic mock mode: изменения живут в памяти сессии, SMS/письма/перевод оператору симулируются, реальные деньги и полисы не затрагиваются. Укажи дату симуляции из набора, известные противоречия и неподдержанные действия, если они остались.
5. Запиши pre-existing starter/DSR/TTS/model integrations, реально созданную за конкурс логику и фактические результаты eval. Обнови docs/PROGRESS.md, DEMO.md и SUBMISSION.md, не подменяй историю.
6. Проведи независимое демо на другой машине/браузере или хотя бы в чистой сессии: русская реплика, казахская, смешанная, два намерения, уточнение, подтверждение, оператор, отказ провайдера. Никакого фиксированного «счастливого» сценария как единственной проверки.
7. Подготовь короткую демонстрацию: говорить произвольную фразу → показать DSR → объяснить маршрут и альтернативу → выполнить сценарий по данным → показать реальные замеры. Не утверждай, что голосовая деградация только до текста удовлетворяет обязательному голосовому требованию.

## Проверка

Другой участник воспроизводит приложение по README; есть живой голос и трассировка; проверенный commit/артефакты сданы в репозиторий организатора. В финальном отчёте отдельно перечислены проверено / не проверено / известные ограничения.
