# Фаза 2 — DSR и слышимый голос

## Задание

1. Подключи браузерный микрофон, явную кнопку начала сессии и текущий speech-транспорт. При отсутствии подходящего транспорта добавь один WebSocket на существующий node:http сервер, с серверными соединениями к провайдерам. Не используй H3 2.x API. Проверь WS proxy в Vite, production upgrade и остановку соединений при завершении сессии/сервера.
2. Подай одно и то же аудио в OpenAI STT/VAD и Yandex. Используй реальный аудиоформат текущих адаптеров; ресемплируй при необходимости. Нельзя объявлять 48 kHz как 24/16 kHz без конвертации, отправлять WebM как raw PCM или добавлять неожиданный WAV-header. Избегай повторной регистрации микрофона на каждый ход.
3. Используй OpenAI VAD как принятый командой источник границ хода; согласуй сегменты Yandex с теми же временными интервалами. Сохраняй обе гипотезы, статус partial/final/refinement, provider item IDs и время готовности. Один final провайдера не равен новому пользовательскому ходу. Не путай STT-модель OpenAI с LLM gpt-realtime.
4. Повторно используй существующую политику согласования DSR. Оберни её явным контрактом: на выходе один подтверждённый текст хода, исходные варианты, причина выбора, деградация и неоднозначные поля. Не вводи правило «Yandex всегда лучше на казахском» без результатов. Не сравнивай confidence разных провайдеров как одну откалиброванную шкалу.
5. Добавь ограниченное ожидание второго STT, настраиваемое и видимое в trace. Не жди бесконечно и не запускай два handleTurn через Promise.race. При отказе одного провайдера продолжай с доступным текстом, явно показывая degraded. Опоздавшая версия после финализации — только диагностика, не повторная маршрутизация, не переписывание подтверждения и не запуск операции.
6. При существенном конфликте цифр, номера полиса, телефона или отрицания пометь поле неоднозначным и переспроси. Не достраивай номер из mock-данных. Не вызывай отдельную LLM «для склейки STT» на каждом ходе; при необходимости маршрутизатор уже может получить ограниченные альтернативы, но подтверждение действия не должно строиться на неразрешённом конфликте.
7. Передай финализированный TurnInput в тот же handleTurn, что использовался для текста. Отдели транскрипционную сессию от контекста LLM. У LLM не должно быть возможности самостоятельно ответить на сырой звук прежде route_turn. В speech-to-speech сессии, которую приходится переиспользовать, сохраняй VAD, отключай автоматический ответ и явно ограничивай входы LLM согласованным текстом.
8. Текст ответа передай серверному ElevenLabs V3 адаптеру. Точный model ID и voice ID читать из конфигурации, не заменять модель ради демо без явного решения. Используй уже работающий протокол. Не переносить параметры обычного TTS WebSocket на v3 автоматически: для v3 есть отдельный Text-to-Dialogue WebSocket. HTTP streaming допустим как простейший путь, когда входной текст уже готов.
9. Проиграй реальные байты в браузере с корректным форматом. Введи playbackId и событие фактического начала воспроизведения. После остановки/новой сессии старые чанки не проигрывать. На перебивании отменять generation/TTS, когда это поддержано, и в любом случае прекращать локальное воспроизведение. Не добавлять весь сгенерированный, но не услышанный текст как произнесённый. Минимум — помечать ответ interrupted и не считать, что клиент слышал оставшуюся часть.
10. Для первого прохода допустим управляемый режим «говорить/остановить» с защитой от эха. Не ломать работающий путь ради нового full-duplex движка. Проверить localhost или HTTPS и пользовательское разрешение звука.

## Проверка

Новая фраза через микрофон даёт обе STT-гипотезы, один итоговый ход, маршрут, содержательный ответ и слышимый ElevenLabs V3. Повторить на русском, казахском и смешанной речи. Отключить один STT и проверить деградацию без дублирования. Текстовый путь остаётся рабочим.
