# Реализация Voice Router: ответственность и проверяемый путь

Цель — один браузерный голосовой робот для кейса Halyk Bank, который выбирает сценарий через LLM, понимает русский/казахский и показывает решение супервизору. Это не новая платформа и не соревнование STT/TTS-моделей.

Требования: [TASK.md](../../TASK.md). Запуск, все переменные и внешние API: [корневой README](../../README.md). Проверенная готовность: [STATUS.md](../STATUS.md). Файлы `phases/` — план и критерии будущего завершения, а не журнал уже выполненной работы.

## Что происходит после решения LLM

Модель предлагает сценарии, confidence, причину, альтернативы, язык и слоты. Сервер не доверяет произвольному ID или неподходящему параметру: валидирует ответ по схеме/каталогу. Только невалидный структурированный ответ даёт одну попытку repair; сетевые ошибки не маскируются успешной заглушкой.

Policy учитывает системные намерения и обязательный handoff; для предметного маршрута использует пороги 0,75 / 0,45, серию низкой уверенности и недостающие слоты. Срочные SC11, SC15, SC38 идут раньше обычных. Ответ строится из привязанных фактов или безопасного текста каталога; не из свободно придуманных страховых правил.

Пример: «Полисімді ұзарту керек, и ещё добавить водителя» должен дать SC27 + SC04 и уточнение нужных данных. «Только что попал в ДТП» должен приоритизировать SC11. Это ожидания каталога, которые нужно проверить, не заранее записанный ответ UI.

Сейчас `actions.json` и `mock_backend.json` загружаются как данные, но исполнителя с идентификацией и подтверждениями нет. Нельзя описывать `plan.outcome = "handoff"` как реальный перевод оператору или `completed` как проведённую операцию.

## Голос и ошибки

Вход браузера — signed PCM16 little-endian, mono, 16 кГц, кадр 320 samples. OpenAI получает 24 кГц после ffmpeg. Yandex получает 16 кГц. DSR хранит обе гипотезы, отдаёт приоритет согласованному финальному OpenAI-тексту либо использует Yandex fallback. Конфликт чисел/отрицания ведёт к переспросу до LLM-маршрута.

ElevenLabs возвращает PCM16 16 кГц. Сервер добавляет к исходящему бинарному пакету playback UUID, чтобы клиент отбросил запоздалое аудио. Клиентские подтверждения воспроизведения отличают выданный сервером текст от действительно проигранного ответа.

Ошибки провайдеров не равны ошибке HTTP-схемы:

- без OpenAI controller возвращает `unavailable` без выдуманного решения;
- без обоих STT голосовой ход получает `STT_UNAVAILABLE`;
- при одном доступном STT DSR явно помечает деградацию;
- без ElevenLabs key/voice результат текста остаётся доступен, `tts.status` — `unavailable`;
- ошибка TTS после начала потока может оставить частично проигранный ответ — это не полная доставка.

VAD-граница отправляет Yandex EOU и прекращает передачу новых PCM провайдерам. DSR ждёт авторитетный OpenAI final по текущему item ID до ограниченного дедлайна; поздние события не запускают второй ход. При TTS-ошибке доступны безопасные `kind`/`httpStatus` и объём аудио, без ключей и сырого ответа провайдера. Начало аудио объявляется с первым PCM-фреймом.

Правая панель получает последний результат text/voice без повторного LLM-запроса; контекст сессий при этом остаётся раздельным. Часть trace уже измеряется, но единая сквозная метрика «конец речи → первый звук» ещё не подтверждена. Не складывайте перекрывающиеся этапы в обещание 1,5 с.

## Разработка, запуск и проверки

Из корня:

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm run check
pnpm run verify
```

Окно dev — `http://127.0.0.1:5173`. Без `.env`/ключей приложение запускается, но LLM/речь недоступны. Только `doctor` требует файл локально: `pnpm run setup` создаёт пустой шаблон; альтернативно `CI=true` разрешает проверку без файла.

Для live нужны OpenAI key; для второй STT-гипотезы — четыре Yandex-поля; для звука — ElevenLabs key и **существующий Voice ID, добавленный в аккаунт этого ключа**. Локальному OpenAI STT нужен ffmpeg. Никаких секретов в `src/shared`, `src/web`, `VITE_*` или trace. Полная конфигурация и требования каждого API — [в корневом README](../../README.md#настройки-полный-справочник-без-доступа-к-чужому-env).

Для production: `pnpm run build`, `NODE_ENV=production`, запуск `dist/server/index.js` с runtime-зависимостями и каталогом `data/`. Compose по умолчанию не передаёт ключи; вариант Dockerfile с ENTRYPOINT `env -u` дополнительно удаляет их. Для live использовать описанный [Node-деплой](../../README.md#production-и-деплой). До публикации нужны HTTPS/WS и внешнее ограничение доступа/расходов.

Локальные регрессии:

- `voice-router-baseline.test.ts` — каталог/схемы/необязательная конфигурация;
- `voice-router-phase1.test.ts` — prompt, repair, policy, сессии и ответы с fake model;
- `voice/*.test.ts` — DSR, STT/TTS, WS, отмена, PCM и доставка звука с подменёнными провайдерами;
- `voice-router-tz-acceptance.test.ts` — контракты диалога и trace со scripted model, не точность настоящей LLM;
- `api.test.ts` и web-тесты — HTTP-контракты, ошибки, API-клиент и SSR страницы.

Отдельно, только при согласованном расходовании квоты: `pnpm run eval:router` и затем `python data/voice-router/evaluate.py artifacts/router-eval/predictions.json data/voice-router/dev_utterances.json`. Одиночный dev-eval не проверяет контекст диалога и микрофон.

## Границы изменений

Сохранять один пакет ESM, Node 24, H3 **1.x**, Vue `script setup`, явные относительные `.ts`-импорты. Не вводить ORM, очереди, SIP, векторную БД или 40 отдельных агентов без потребности задачи. Исходные данные и ожидаемую разметку не менять ради результата.

Следующий проверяемый шаг выбирается из открытых пунктов, проходит `check`/`verify` и записывается в [progress/](../progress/) с обновлением [STATUS.md](../STATUS.md). Моки, живой API и деплой всегда описываются раздельно.
