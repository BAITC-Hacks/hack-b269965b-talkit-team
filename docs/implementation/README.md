# План реализации Voice Router

Этот каталог разбивает пятичасовой MVP на проверяемые вертикальные шаги. План опирается на существующий blank project и не разрешает переносить платформу TalkIt целиком.

Целевой стек: один пакет pnpm, Node.js 24, TypeScript, H3 1.x, Vue 3, Vite и Zod. Целевые провайдеры команды — OpenAI STT/VAD + Yandex SpeechKit для DSR, `gpt-realtime` для маршрутизации и ответа, ElevenLabs V3 для TTS.

## Основной вертикальный путь

```text
Микрофон
  → OpenAI STT/VAD ─┐
                    ├→ один финализированный DSR-транскрипт
  → Yandex STT ─────┘
       → общий handleTurn()
       → gpt-realtime / route_turn
       → Zod + catalog validation
       → decision policy
       → mock executor / knowledge facts
       → grounded response
       → ElevenLabs V3
       → воспроизведение + supervisor trace
```

Текстовый ввод подключается к `handleTurn()` после DSR и не получает отдельную упрощённую бизнес-логику.

1. [`../../AGENTS.md`](../../AGENTS.md);

6. нужные исходные JSON и локальные инструкции рядом с изменяемым кодом.

Затем:

1. Проверьте фактическое состояние реализации — план может отставать от кода.
2. Внесите один законченный вертикальный шаг.
3. Запустите `pnpm run check`; перед контрольной точкой — `pnpm run verify`.
4. Запишите реальный результат в `docs/progress/` и обновите `docs/STATUS.md`.
5. Сообщите, что работает, что проверено, что не проверено и какой критерий остаётся открытым.

Не отмечайте фазу завершённой по наличию файлов или mocked unit-тесту.

## Архитектурные границы

- Сохранять один пакет и существующее разделение `src/server`, `src/web`, `src/shared`.
- Серверные ключи и `process.env` не должны попадать в `src/shared` или browser bundle.
- Использовать явные относительные импорты `.ts`; server build переписывает их в `.js`.
- Не использовать TypeScript-конструкции, несовместимые с native type stripping: enums, decorators, namespaces и constructor parameter properties.
- LLM принимает решение по всему каталогу и границам `not_this_if`; expected-разметка никогда не попадает в runtime prompt.
- Модель возвращает предложение маршрута. Сервер проверяет схему, ID, слоты, уверенность и право выполнения действия.
- Необратимое действие выполняется только серверным кодом после отдельного явного подтверждения конкретного `pendingAction`.
- Все действия остаются синтетическими и изолированными в demo session. Никаких реальных SMS, звонков, полисов или платежей.
- База знаний и mock backend — единственные источники предметных фактов. Не дополнять страховые правила из интернета.
- Обычный ход должен укладываться в одно LLM-решение и одну генерацию ответа; repair допускается только при невалидном структурированном выводе.
- Не добавлять без конкретной необходимости БД, ORM, Redis, очереди, SIP, RAG/vector DB, DI-контейнер, event bus, agent framework или 40 отдельных агентов.

## Фактические extension points

```text
data/voice-router/                       исходный kit, не редактировать
data/voice-router-app/                   производные mapping/binding-файлы
src/shared/voice-router.ts               публичные DTO и runtime-схемы
src/server/features/voice-router/
  catalog.ts                             загрузка, prompt и catalog validation
  model.ts                               интерфейс LLM-провайдера
  openai-realtime.ts                     server-side gpt-realtime transport
  router.ts                              route_turn tool и repair
  policy.ts                              confidence/system/urgency policy
  state.ts                               ограниченное in-memory состояние
  controller.ts                          orchestration и базовая trace
  routes.ts                              HTTP turn/reset
src/web/features/voice-router/realtime/  браузерный аудиотранспорт, ещё не подключён
```

Новые части добавляются только когда они нужны очередному вертикальному шагу. Ожидаемые места:

- `src/server/features/voice/` — server WebSocket, DSR, STT и TTS;
- `src/server/features/voice-router/actions.ts` — mock executor и подтверждения;
- `src/web/features/voice-router/` — страница, composable и trace-панель;
- `scripts/eval-router.mjs` — воспроизводимый прогон dev-реплик;
- `tests/voice-router/` либо существующий плоский `tests/` — unit/integration-проверки по принятой структуре.

Это точки расширения, а не требование создать пустые файлы заранее.

Это бюджет команды, а не гарантия выполнения и не официальное время дедлайна. Браузерный UI, speech-интеграции и deployment проверяются рано, чтобы не обнаружить блокер в конце. После третьего часа объём не расширяется.

При нехватке времени первыми исключаются оформление, эмоции, статистический dashboard, редактор каталога, сравнение моделей и сложные оптимизации. Нельзя исключать реальный голос, LLM-выбор, RU/KK, trace, подтверждения, воспроизводимость и deployment.

## Критерий завершения шага

Шаг завершён, когда:

- работает реальный путь от входа до наблюдаемого результата;
- входы и выходы валидируются;
- ошибки не превращаются в фиктивный успех;
- критическое правило покрыто тестом без платного API;
- живая внешняя интеграция проверена отдельно, если шаг её заявляет;
- `check` пройден, а на контрольной точке пройден `verify`;
- фактический результат записан без придуманных метрик, commit или deployment.
