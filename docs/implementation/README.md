# Voice Router — задания coding-агенту

Основа: существующий HackAlem blank project. Не создавай новый проект и не переноси целиком TalkIt.
Пользовательский стек: DSR (OpenAI STT + VAD и Yandex SpeechKit), ElevenLabs V3, gpt-realtime.
Ниже приведён предлагаемый план реализации, а не утверждение о готовности кода или разрешениях организаторов.

## Как работать

Начни с AGENTS.md, docs/README.md, docs/STATUS.md, TASK.md и назначенной фазы. Для первичного разбора задачи интегратор читает весь комплект организаторов; для локального изменения загружай связанные данные и инструкции по карте docs/README.md, не всю историю проверок. Текущий репозиторий приоритетнее примеров путей в этих инструкциях. Сохраняй предоставленные организатором файлы. Выполняй выданную фазу небольшими проверяемыми шагами; не заменяй реализацию ещё одним архитектурным планом.

После каждой фазы отчитайся: что работает; какие файлы изменены; какие команды действительно запущены; реальные ошибки/ограничения; следующий незакрытый критерий. Не объявляй фазу завершённой без её проверки. Обновляй docs/STATUS.md и добавляй отдельную фактическую запись в docs/progress/. Не подделывай коммиты, даты, измерения или результаты API.

## Неизменяемые решения

- Один пакет pnpm; существующие Node.js/TypeScript/H3 1.x/Vue/Vite/Zod. Не мигрировать на H3 2.x, монорепозиторий или другую платформу. Сохранять явные относительные .ts-импорты и ограничения native type stripping из AGENTS.md.
- Новое приложение: один браузерный голосовой симулятор с текстовым резервным вводом, LLM-маршрутизацией и настоящей трассировкой.
- DSR и TTS — повторно используемые адаптеры, а не новое исследование STT. Исходники интеграций пока не приложены к этому пакету; не выдумывать их пути, методы и алгоритмы. Читать доступный код, переносить только разрешённые зависимости. Не изменять исходный TalkIt.
- Зафиксировать starter и речевые компоненты как pre-existing, учитывать разрешения организатора. Отсутствие разрешения блокирует соответствующий импорт, а не всю независимую работу над новым маршрутизатором.
- Сохранить gpt-realtime как стартовую LLM. Голос синтезировать ElevenLabs V3; не включать конкурирующий OpenAI audio output.
- Разделить входной STT/VAD-контур и контекст принятия решений. LLM принимает согласованный текст DSR, а не самостоятельно отвечает на сырой звук до согласования. При повторном использовании одной сессии явно изолировать входы; отключения автогенерации недостаточно для удаления уже добавленного аудио из контекста.
- Не более двух обычных LLM-генераций на простой ход: структурированное решение маршрута, затем ответ по результатам исполнения. Это целевой путь, не обещание верхней границы для всех ошибок и сложных диалогов. Не создавать отдельных LLM-агентов для языка, эмоций, триажа, каждого сценария и озвучки.
- Источник фактов: knowledge_base.json и mock_backend.json. Не брать реальные страховые правила из интернета. Не исправлять противоречия источников молча: записывать их и принятую трактовку.
- Не обучать intent-классификатор, не хардкодить тестовые реплики, не передавать expected-разметку в runtime или промпт.
- Все операции — синтетические моки. Не отправлять настоящие SMS, письма, деньги и не подключать реальные полисы/звонки.
- Проверка подтверждения необратимого действия — серверный код. Текст модели «подтверждено» не даёт права исполнять.
- Ключи только на сервере, никогда в VITE\_\*, публичных DTO, Git и трассировке. Без production-данных и аудиозаписей реальных клиентов.
- Не добавлять БД, auth, ORM, очереди, Redis, SIP, RAG/vector DB, DI-контейнер, event bus или agent framework без отдельной необходимости. Состояние демо — в памяти процесса.

## Основной маршрут данных

Микрофон → существующий DSR (OpenAI STT/VAD + Yandex) → один финализированный ход → gpt-realtime/route_turn → серверная валидация и политика → mock-исполнитель → текстовый ответ gpt-realtime → ElevenLabs V3 → браузер.

Текстовый ввод подключается к тому же обработчику непосредственно после DSR. Интерфейс показывает все этапы; не строить отдельную упрощённую бизнес-логику для текста.

## Пятичасовое окно команды

| Фаза | Окно      | Результат                                               |
| ---- | --------- | ------------------------------------------------------- |
| 0    | 0:00–0:15 | Рабочая основа, источники, договорённые контракты       |
| 1    | 0:15–0:55 | Настоящий текстовый путь через LLM и первый eval        |
| 2    | 0:55–1:40 | Микрофон → DSR → ответ → ElevenLabs V3                  |
| 3    | 1:40–2:50 | Контекст, несколько намерений, действия и подтверждения |
| 4    | 2:50–3:25 | Полная панель супервизора и измерения                   |
| 5    | 3:25–4:30 | Исправления по eval и голосовым испытаниям              |
| 6    | 4:30–5:00 | Чистый запуск, документация, сдача                      |

Это бюджет работ, не гарантия выполнения. При трёх исполнителях проверка speech-адаптеров и создание UI начинаются параллельно фазе 1. Базовая трассировка появляется уже в фазе 1, а не впервые в фазе 4. После третьего часа не расширять согласованный объём.

При нехватке времени исключать оформление, редактор каталога, эмоции, сравнение моделей и сложные оптимизации. Не вырезать реальный голос, LLM-выбор, русско-казахский маршрут, трассировку, защиту подтверждений и воспроизводимость.
