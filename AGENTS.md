# HackAlem Starter — инструкции для разработчика и Codex

## Цель

За пять часов создать один работающий конкурсный сценарий. Это не разработка новой платформы.
Перед задачей прочитай README.md, TASK.md и docs/compliance/PREEXISTING.md; текущее состояние — в docs/STATUS.md.

## Правила

- Этот starter создан заранее. Не выдавай его за результат конкурсных пяти часов.
- Использовать заранее созданный каркас только после разрешения организатора.
- Во время конкурса вся новая работа — в предоставленном организатором репозитории.
- Не меняй production TalkIt или соседние репозитории. Его API — только объявленная зависимость.
- Не подделывай даты, коммиты, почасовой прогресс и результаты тестов.
- Не сохраняй токены, персональные данные, дампы production и логи с секретами в Git.
- Не подключай внешние действия, расходы или отправку сообщений без контроля доступа и подтверждения.

## Стек и границы

- Один пакет pnpm, ESM, Node.js 24, H3 **1.x**. Не используй API H3 2.x.
- src/server — сервер, конфигурация и ключи. Никогда не импортируется фронтендом.
- src/web — Vue 3. script setup, небольшие компоненты, понятные состояния интерфейса.
- src/shared — безопасные общие Zod-схемы и типы. Никакого process.env и серверных ключей.
- Новые сценарии — src/server/features/<feature> и src/web/features/<feature>.
- Используй явные относительные импорты .ts. Серверная сборка переписывает их в .js.
- Не добавляй enums, decorators, namespace, constructor parameter properties: dev использует native type stripping.
- Не добавляй DI-контейнер, event bus, очереди, микросервисы, монорепозиторий или ORM без конкретной потребности текущей задачи.
- Сначала свяжи ввод → сервер → реальную механику → ответ. Не заполняй приложение заранее успешными ответами.
- Моки и демонстрационные данные подписывай явно; отсутствие внешнего API не превращай в «успешный» результат.

## Работа

1. Прочитай существующий код и границу текущей задачи.
2. Внеси один законченный, проверяемый шаг; не редактируй чужие файлы параллельно без согласования.
3. Запусти pnpm run check. Перед контрольной точкой — pnpm run verify.
4. Добавь фактические результаты в docs/progress/ и обнови краткий docs/STATUS.md.
5. Кратко сообщи: что изменилось, чем проверено, что не работает. Ничего не выдумывай.

## Команды

pnpm dev — разработка; pnpm run check — типы и тесты;
pnpm run verify — диагностика, типы, тесты, сборка и smoke;
pnpm run format — форматирование; pnpm run smoke -- <URL> — проверка развёрнутого API.
