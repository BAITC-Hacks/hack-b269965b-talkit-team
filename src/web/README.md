# Веб-симулятор Voice Router

Vue 3 интерфейс конкурсного кейса Halyk Bank: клиент говорит в микрофон или вводит текст, а супервизор видит выбор сценария из каталога Saqta Insurance. Выбор делает серверный LLM, не браузерный классификатор.

`App.vue` открывает **`pages/VoiceRouterPage.vue`**. Echo-код сохранён как инфраструктурный пример, но не является главной страницей.

## Что делает пользователь

1. Открывает `http://127.0.0.1:5173` в dev или адрес production-приложения.
2. Для текста вводит, например, «Деньги списались, а полис не оформлен». Ожидаемый по каталогу маршрут — SC30; справа отображаются фактический сценарий, причина, альтернатива и timings.
3. Для голоса нажимает визуализатор «Позвонить» и разрешает микрофон. После «Слушаю вас» говорит на русском, казахском или смешанно.
4. VAD завершает реплику после паузы; «Закончить реплику» доступно как ручной резерв. В голосовой карточке появляются STT-гипотезы, DSR, результат LLM и статус озвучки.
5. «Говорить снова» начинает следующий ход. «Отменить реплику» / «Прервать ответ» останавливает текущую операцию, повторное нажатие визуализатора завершает звонок.

Пример смешанной фразы: «Полисімді ұзарту керек, и ещё добавить водителя» — ожидание SC27 + SC04. Это пример проверки, не гарантированный результат модели и не предзаполненный успешный ответ.

Текстовый чат и голосовая карточка используют **разные сессии**. Новая текстовая сессия не переносит и не сбрасывает контекст звонка. Правая панель относится к текстовому каналу; голосовая диагностика находится внутри карточки звонка.

## Состояния, ошибки и trace

Голосовой клиент проходит `idle → connecting → handshaking → ready → recording → waiting → playing`; есть отдельные `closing/closed/error`. UI не должен изображать запись до согласования с сервером или полную доставку до окончания playback.

- Нет OpenAI: текстовый API возвращает `unavailable`, а не правильный сценарий-заглушку.
- Нет доступного STT: голосовой ход получает `STT_UNAVAILABLE`.
- Один STT не ответил: DSR явно помечает деградацию.
- Распознавания расходятся в числах/отрицании: переспрос вместо передачи сомнительных данных в router.
- Нет ElevenLabs key/voice: текст может быть получен, но `tts.status = "unavailable"` и нет озвучки.
- Ошибка или прерывание воспроизведения не считается полностью доставленным ответом.
- Неизмеренный timing отображается «—», не `0 ms` и не вымышленное `500 ms`.

Текстовая панель выводит основной сценарий, первую альтернативу, причину, язык и доступные времена. Голосовая карточка выводит обе гипотезы, DSR, выбранные сценарии/альтернативы, измеренные routing/answer и статус доставки аудио. Это ещё не полный supervisor-dashboard со статистикой ошибок, действиями и историей.

`Total` справа — сумма доступных серверных этапов. Это **не** latency от конца речи до первого услышанного аудио; такая метрика требует отдельного сквозного замера. Реальная точность и достижение ориентиров 500 мс / 1,5 с здесь не заявлены.

## Аудиоконтракт

Браузер обращается к своему серверу по `/api/voice-router/ws`. Сначала JSON handshake с версией, session/turn/sequence и подтверждением формата, затем аудио только после `audio.ready`.

Вход: signed little-endian PCM16, mono, 16 000 Гц, 320 samples = 640 байт на кадр. Это raw PCM, не WebM/Opus/WAV. Исходящий TTS может приходить более крупными пакетами; перед PCM сервер добавляет 36-байтный playback UUID. Лимит микрофонного кадра нельзя применять ко всему входящему TTS-пакету.

WebSocket-события валидируются, устаревшие turn/playback ID отбрасываются, очереди ограничены. Повторные STT partial/final не должны порождать второй бизнес-ход. Отмена закрывает соответствующий ввод/вывод. Схема протокола единая: [voice.ts](../shared/voice.ts).

## Запуск и конфигурация без секретов в браузере

Из **корня репозитория**, не из `src/web`:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Нужны Node.js 24.21+ (24.x) и pnpm 10.28.0. Vite слушает `127.0.0.1:5173` и проксирует `/api`, включая WS, на `127.0.0.1:3000`. `pnpm run dev:web` отдельно запускает только frontend: для маршрутизации нужен сервер `pnpm run dev:api`.

Без `.env` и ключей интерфейс запускается, health/echo работают; text/voice показывают недоступность провайдеров. Демо-результаты автоматически не подставляются.

Все настройки подаются **серверу**:

| Что нужно                     | Настройка                                                                                                                               |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Реальный LLM и OpenAI STT/VAD | `OPENAI_API_KEY`; для STT также ffmpeg в серверном `PATH`                                                                               |
| Вторая гипотеза Yandex        | `YANDEX_SERVICE_ACCOUNT_ID`, `YANDEX_SERVICE_ACCOUNT_KEY_ID`, `YANDEX_SERVICE_ACCOUNT_PRIVATE_KEY`, `YANDEX_FOLDER_ID`                  |
| Озвучка                       | `ELEVENLABS_API_KEY` + `ELEVENLABS_VOICE_ID`: существующий голос, уже добавленный/загруженный в аккаунт этого API-ключа и доступный ему |

Модели/эндпоинты/формат PEM и поведение при неполной конфигурации подробно описаны [в корневом README](../../README.md#настройки-полный-справочник-без-доступа-к-чужому-env). Нет отдельного frontend API key. Не использовать `VITE_*` для секретов и не импортировать `src/server` в браузер.

## Production и браузерные требования

`pnpm run build` создаёт `dist/web` и `dist/server`. UI раздаёт H3 при **`NODE_ENV=production`** на том же порту, что HTTP и WS. Одной статической публикации `dist/web` недостаточно: нужен backend с `data/` и зависимостями.

Compose по умолчанию запускает приложение без переданных ключей. Если образ собран с ENTRYPOINT `env -u`, ключи дополнительно удаляются при старте. Такой запуск нельзя принимать за live voice deployment. Команды Node/Docker, HTTPS proxy и защита расходов: [деплой](../../README.md#production-и-деплой).

Для микрофона нужны HTTPS либо localhost/loopback, поддержка AudioWorklet/Web Audio и разрешение пользователя. HTTP по LAN-IP может открыть страницу, но не дать микрофон. HTTPS-страница использует WSS; proxy должен сохранять внешний Host/Origin и пропускать Upgrade. У приложения нет встроенного пользовательского входа — доступ к платному демо ограничивается снаружи.

## Проверки

Из корня:

```sh
pnpm run check
pnpm run verify
```

Локальный `doctor` внутри verify требует `.env`: создайте пустой шаблон через `pnpm run setup` либо используйте `CI=true` для проверки без файла. Значения ключей не нужны.

Автотесты покрывают HTTP-клиент, ошибки, SSR VoiceRouterPage, PCM/ресемплинг, протокол/ack, неизменяемые snapshots, отмену, большие TTS-пакеты, playback timeout и уровень микрофона с подменёнными браузерными API. Они не включают настоящую запись/звук браузера и платные провайдеры.

Ручная live-проверка после настройки доступа:

1. Отказ в микрофоне → понятная ошибка; повторное подключение не создаёт два capture.
2. RU, KK и mixed → корректные транскрипт/маршрут/ответ, не только красивый визуализатор.
3. Следующая реплика и смена темы → актуальный контекст той же голосовой сессии.
4. Прерывание/отключение → прекращение звука и отсутствие устаревших результатов.
5. Недоступный STT/TTS → видимая ошибка/деградация, без ложной полной доставки.
6. HTTPS с другого устройства → разрешён микрофон, проходит WSS, слышен ответ.

Результаты фиксируются в [docs/progress/](../../docs/progress/) и [STATUS.md](../../docs/STATUS.md). Тестовый SSR не является свидетельством live-приёмки.
